# Screenshot capture manifest

Every image under `docs/guides/images/`, with what it shows and how to recapture it. Regenerate after any UI change that alters one of these screens.

## Capture source: the demo firm

Every shot is taken against **Lumilex & Partners**, the fictional demo firm on the test project ([docs/demo-instance.md](../../demo-instance.md)). Its staff, clients, matters, invoices and addresses are all invented, and it is reset nightly, so nothing in a screenshot needs scrubbing and opening a dropdown or a modal leaves no lasting trace. **Never capture against a real firm's data** — the set previously in this folder was taken on the origin firm's production database and showed its logo, staff, salaries, invoice numbers and clients.

## Recapture procedure

1. Start the dev server (the "Next.js Dev Server" launch config, or `npm run dev`) with the test project's `.env.local`. Demo mode (`LUMILEX_INSTANCE_ROLE=demo`) is **not** needed and is better off: without it there is no demo banner, and `/login` shows the ordinary email-and-password form in the demo firm's branding.
2. Use **`http://demo.localhost:3000`** as the origin, never `localhost:3000`. `firm_domains` maps `demo.localhost` to the demo firm and `localhost` to the dev firm, so a demo session on `localhost` is bounced by the host binding to the demo's primary domain (the live demo.lumilex.co, in demo mode).
3. Per page: sign in via `http://demo.localhost:3000/api/dev/team-signin?email=<persona>` (it redirects to `localhost`; ignore that and navigate on `demo.localhost`), navigate, wait until no spinner or skeleton is on screen, hide the Next.js dev overlays (`nextjs-portal,[data-nextjs-toast],[data-next-badge-root],[data-nextjs-dev-tools-button]{display:none!important}`), then capture.
4. Viewport 1440×900, light mode, device scale 1. Annotated shots additionally set `window.__ANNOTATE__` and inject [annotate.js](annotate.js).
5. View every capture before committing it. The demo has no real data to leak, but a redirect, a half-loaded page or the wrong persona is easy to miss.

Santos (`marilou.santos`), **admin** — Grace Bautista (`grace.bautista`), **chief liaison** — Rico P. Delos Santos (`rico.delossantos`). The demo's liaison officer has no login, so the liaison-officer shots are taken as the chief liaison, who reaches the same self-serve pages. No demo persona holds `super_user`, so the one super-user-only page needs a temporary role change (see its row). [anonymize.js](anonymize.js) and [terms.sql](terms.sql) remain for anyone who ever has to capture against real data; the demo set does not use them.
